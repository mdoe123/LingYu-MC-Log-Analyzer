# 玩家版解决方案：进游戏就崩（Oculus × Embeddium）

> 适用场景：Minecraft 1.20.1 + Forge，安装 Oculus 与 Embeddium 后，启动到加载画面时崩溃。
> 文中版本号来自本次分析示例，实际请以模组发布页的兼容说明为准。

## 一句话说明

两个“让画面更流畅 / 支持光影”的模组抢了游戏的同一个位置，游戏在准备画面时失败。

**不是电脑坏了，也不是存档坏了。**

## 先做这三件事（约 5 分钟）

1. **备份**：把 `.minecraft/mods` 整个文件夹复制一份到桌面，命名 `mods-备份`。
2. **最快验证**：把 `oculus-1.7.0.jar` 从 `mods` 里移到桌面（暂时不用光影），启动游戏。
3. **能进游戏**：说明问题就是 Oculus 与 Embeddium 的组合；按下面“想继续用光影”处理。

## 想继续用光影：按顺序试

每一步只改一个地方，改完启动一次；能进就停，不用继续往下做。

1. 把 **Embeddium 换成 0.3.32**（或退到 0.3.25），Oculus 保持 1.7.0，启动。
2. 还崩：删掉 `config/oculus` 文件夹，以及 `shaderpacks` 里的缓存文件，再启动。
3. 还崩：只留一个渲染类模组（Oculus 或 Embeddium 二选一），确认能进后，再把另一个加回来验证。
4. 可选：先关闭光影包再启动，排除光影本身的问题。

## 不要做

- 不要同时安装 OptiFine、Embeddium、Sodium 这类“优化画面”的模组，它们会互相打架。
- 不要删除 `saves` 存档；这次崩溃与存档无关。
- 不要盲目把内存调到最大；本次日志里内存是 8 GB，并没有内存不足。
- 不要一次改好几个模组，否则无法判断是哪一步生效。

## 怎么算修好

- 能进入主菜单；
- 能进入一个世界，玩 5–10 分钟不崩；
- `logs/latest.log` 里不再出现 `Mixin apply for mod oculus failed`。

## 还不行：这样求助

把下面三样发给帮你的人，或贴到求助帖：

1. `.minecraft/logs/latest.log`
2. `.minecraft/crash-reports` 里最新的一份 `.txt`
3. 一句话说明：改了什么、做到第几步后发生变化

可直接复制这段填写：

```text
版本：1.20.1 / Forge 47.3.0 / Java 17
问题：启动到加载画面崩溃，日志提到 oculus 与 embeddium
已尝试：...
结果：...
```

## 以后怎么避免

- 加模组一次只加一个，加完启动一次；
- 光影 / 优化类模组只留一套，别混装；
- 大改模组前，先备份 `mods` 与 `saves`；
- 整合包升级前，先看发布页有没有写“需要某个特定版本的 Oculus / Embeddium”。
